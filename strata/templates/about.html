What Strata does

A regulatory proceeding arrives as a sequence of versions of roughly the same document. Strata diffs each new version against the one before it, has a model say what each change does, and then checks every quoted passage against the source text mechanically before a person sees it. Verified changes are mapped to the company's own obligations, and the company graph is walked to find the projects and documents downstream, so each item of work names the node it affects and the path that reached it. Anything the system cannot verify or is not confident about goes to an expert instead of to the person who owns the work.

The data carries deliberate traps, because the point of the prototype is what it refuses to get wrong:

  • A footnote renumbering and a cosmetic rewording that change no duty. Both must come back not material.
  • One paragraph that shortens two deadlines at once, which must produce two claims and reach two obligations.
  • A new penalty with no matching obligation in the company graph. No existing node is the right answer, so it is escalated for a person to create one.
  • An obligation removed entirely in the final version, whose quote can only come from the previous version because the text no longer exists.
  • A paragraph renumbered after an insertion, which must not be reported as a change.
  • A distractor: a nearby paragraph containing the same number in a different context, which the verifier rejects if it is quoted.

How the model calls are cached

There are exactly two model call sites: one that reads a change and returns claims, and one that maps a verified claim to obligations. Every call is keyed by a hash of the model, the prompt version, the messages and the response schema, and the responses are committed to the repository, {{ cache_entries }} of them. The tests and the evals run from that cache with no API key and no network.

One consequence is worth knowing before you click: the recorded responses for the final version list the obligation an expert creates while resolving the previous version's expert queue. Resolve that queue first, and accept the prefilled values, or the next version builds a prompt that was never recorded. The app handles it, rolling the run back and saying so, rather than failing.

A suggested path

  1. On the review center, read one material change: the summary, the quote, the badge, and the paths under it.
  2. Open the collapsed "not material" block and see what was filtered out, including the footnote renumbering.
  3. Go to the expert queue. The new penalty is there because no existing obligation fits. Create it with the prefilled form; the second item about the same duty offers to link to what you just made.
  4. Load the next version from the sidebar. The change to the same penalty now links to the obligation you created.
  5. Open the audit page and roll back to an earlier sequence number. The review center changes; the log does not shrink.
