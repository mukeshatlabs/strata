STEP 4: VERIFY (strata/verify.py, functions: normalize, find_quote, verify_claim)
No model. Pure code. Runs once per claim.

============================== THE SIX CHECKS, IN ORDER =======================

Input: a Claim (quote, quote_para_id), the paragraphs, and the Change it belongs to.

1. Which paragraphs may this claim quote from?
     modified change  -> para_id_to OR para_id_from
     added change     -> para_id_to only
     removed change   -> para_id_from only
   If quote_para_id is not one of those  ->  REJECTED, reason wrong_paragraph.
   (Runs before any searching. A real quote from the neighbouring paragraph is
   caught here, not by a failed search.)

2. Normalize both the quote and the paragraph text:
     collapse runs of whitespace to one space
     curly quotes -> straight quotes
     en/em dashes -> hyphen
     non-breaking space -> space
   Keep an offset map so a position in the normalized text can be mapped back to
   the original text.

3. Exact search for the normalized quote in the normalized paragraph.
   Found  ->  candidate match, edit_distance 0.

4. If not found: slide a window the length of the quote across the paragraph and
   compute Levenshtein distance at each offset. Best window with distance
   <= max(3, len(quote) // 25) is a candidate, status "near", distance recorded.
   (100-char quote: 4 edits allowed. A dropped comma passes; a paraphrase fails.)
   Nothing within threshold  ->  REJECTED, reason quote_not_found.

5. Map the candidate back to original offsets (match_start, match_end).
   Does [match_start, match_end) overlap any changed span on the quoted side?
     quoted para_id_to   -> compare against change.spans_to
     quoted para_id_from -> compare against change.spans_from
   No overlap  ->  REJECTED, reason quote_outside_changed_span.

6. Otherwise  ->  VERIFIED (distance 0) or NEAR (distance > 0).

Output: Verification(claim_id, status, match_start, match_end, edit_distance,
                     overlaps_change, reason)

============================ WHY IT IS BUILT THIS WAY =========================

Considered and rejected: asking the model to check its own citations in a second
call (repeats the failure it is meant to catch); exact match only (curly quotes and
line-wrap hyphens in real orders would reject correct quotes and teach users to
ignore the badge).

The wrong_paragraph check runs first because a quote that is real but from the
wrong paragraph would otherwise fail as "not found", and the two mean different
things to a reviewer.

The verifier checks the evidence, not the interpretation. A verified quote with a
wrong summary is possible; that is what the evals and the human review are for.
